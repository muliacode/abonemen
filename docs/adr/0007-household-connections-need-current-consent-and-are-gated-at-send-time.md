# A Household's consent to a Connection expires when what was disclosed changes, and the gate sits at send time

A Connection that carries Household data (email first) needs two switches: the Instance Admin makes it available, then an Owner turns it on for the Household after reading a Disclosure. Consent is recorded with the SMTP host (or mailer name) and the Disclosure version the Owner saw. If the admin points mail at a different server, or a release changes the data or recipients in the Disclosure, sending to that Household pauses until its Owner confirms again. The version changes only when data or recipients change, not for wording. Switches the Owner and admin have saved are kept when the cause of a pause goes away.

Every Household email extends `HouseholdMail`, which asks `Connections::allows()` when the message is actually sent, not when it is queued, so withdrawing consent stops mail already in the queue. A closed gate skips quietly: no retry, no failed job. An architecture test fails the build for any class in `app/Mail` that skips the base class, except an explicit allow-list of account emails, which carry no Household data and depend on the mail setup alone.

We chose this over a derived "mail is configured" switch and over checking at queue time because "nothing leaves the server without consent" must survive a changed mail server, a new release and a backlog. Like the Instance Admin boundary (ADR 0003), it is policy enforced by the application, not cryptography: whoever runs the mail server can read what is sent through it, and the Disclosure says so.
