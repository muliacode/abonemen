# The Instance Admin section is a 404 to outsiders and needs a second factor

The Instance Admin section answers 404, not a login redirect or a 403, to guests and to Users who are not Instance Admins, so that its existence is not confirmed. It lives under a human-readable path that is configurable (`ABONEMEN_ADMIN_PATH`, default `/instance`) and is not the first one an attacker tries. By default an Instance Admin enters it only with confirmed two-factor authentication or a passkey, and an instance always keeps at least one Instance Admin: the last one cannot be demoted or delete their own account.

A hidden path is not a security control and we do not rely on it; it only cuts down probing. What protects the section is signing in plus the second factor, and because the admin boundary is policy, not cryptography (ADR 0003), the one account that can run the instance needs more than a password. The first Instance Admin is made at `/setup`, which needs a token from `.env` and disappears once an Instance Admin exists, so a new instance is never open to whoever finds it first. Registration is closed by default for the same reason: an instance runs for the people its operator chose.

The requirement is an instance setting, on by default and chosen at setup. An operator who does not want it can turn it off, which asks for their password: it is their own security decision, and we say so rather than forcing a choice on every instance. The second factor gates only this section. Everyday sign-in is unchanged, so a Household's Members are not affected.
